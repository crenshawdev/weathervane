<objective>
Cover the trait implementations in `src/error.rs` with a dedicated tests module: the two
`Display` impls (NetworkKind, ParseKind), the `Error` enum's `Display` output for all
eight variants, the PII-scrub contract (NoResults's Display and its WireError conversion
do not carry the query text), the `From<quick_xml::DeError>` mapping, and one
deterministic arm of the `From<reqwest::Error>` classifier.

Purpose: `src/error.rs` is currently untested at the module level. `tests/wire_contract.rs`
exercises `WireError::from(&Error)` end-to-end (which indirectly exercises `Error::Display`
per variant), but there is no module-level test proving Display strings, NetworkKind /
ParseKind display, or the `From` impls in isolation. COV-05 asks for exactly this: "`From`
impls, `Display` output, and `WireError` PII-scrub are covered by tests that assert no
query text or coordinates leak into wire output".

This plan is unique in Phase 4: no code extraction is needed. Every target surface is
already directly testable via `use super::*` from a nested tests module. The one design
choice is how to construct a `reqwest::Error` deterministically without a live HTTP
server — the answer is `reqwest::Client::new().get("").build()` (empty URL fails at the
request-build stage synchronously, no `.await` needed, no network).

Per Phase 3's proven method: baseline + post-plan `cargo llvm-cov` measurements are
recorded in the SUMMARY so the module-target improvement is a measured delta.

Output: one new `#[cfg(test)] mod tests` block at the bottom of `src/error.rs` with
roughly 15-17 fixture-based tests, and two measured llvm-cov numbers in the SUMMARY.
Wire contract stays byte-identical.
</objective>
