<objective>
Make the IP-API geolocation success-branch testable via a small mechanical sync-helper
extraction, then prove all three named location surfaces (geocoding parse, IP-geolocation
parse, saved-location coord matching) plus `uses_imperial_units` with fixture-based
`#[test]` functions.

Purpose: `src/location.rs` is currently near-zero covered for its behavior branches
(the existing tests module only pins the IEEE 754 semantics of the range-contains
predicate — a critical D-05/D-06 anti-regression, but not the parse paths themselves).
The Open-Meteo geocoding transform lives in a private assoc fn
`LocationResult::from_geocoding_result` that is already reachable from the tests module
via `use super::*` — no extraction needed. The IP-API success branch is inline inside
`async fn detect_location` alongside `.await` and lives HTTP; extracting it into
`detected_from_ip_api(data: IpApiResponse) -> Result<DetectedLocation>` makes it testable
without a network. Then the three-arm display_name selection, the coord-range guard, and
the country/region fall-through logic can all be exercised offline.

`SavedLocation::matches_coords` and `uses_imperial_units` are already public sync fns —
they need only tests, no extraction.

Per Phase 3's proven method: baseline + post-plan `cargo llvm-cov` measurements are
recorded in the SUMMARY so the module-target improvement is a measured delta.

Output: one private sync helper (small extraction), an extended `#[cfg(test)] mod tests`
block with roughly 15-17 new tests, and two measured llvm-cov numbers in the SUMMARY.
Wire contract stays byte-identical.
</objective>
