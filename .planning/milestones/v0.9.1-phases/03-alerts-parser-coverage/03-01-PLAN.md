<objective>
Make the two HTTP-inlined regional alert parsers (NWS, BOM) testable via a mechanical
sync-helper extraction that mirrors the existing `air_quality_aqicn.rs::extract_aqi`
idiom, then prove the JSON parsers, the expiry filter, and the shared severity mapping
with fixture-based `#[test]` functions. Also extract the MeteoAlarm feed-level mapping
helper here (used by Plan 02's XML tests) so all production-code changes land in one wave.

Purpose: `src/alerts.rs` is 0% covered (394/394 lines). The NWS and BOM transform logic
is currently trapped inside `async fn fetch_*` closures alongside live HTTP and cannot be
tested without extraction. This plan does the lowest-risk possible cut — moving the
existing `filter_map` bodies into private sync functions with no behavior change — and
banks the first slice of coverage on the two JSON parsers.

Per REVIEWS.md findings 4 & 5 (Codex, incorporated): this plan now also records a
measured `src/alerts.rs` line-coverage baseline (pre-extraction) and post-Wave-1 coverage
number in the SUMMARY, so Plan 02's 65% gate becomes a measured delta rather than an
assumption; and adds small missing-field fallback assertions (NWS defaults + BOM
short_title/warning_type) so the fallback arms don't ship as silently unguarded coverage.

Output: three private sync helpers, a new `#[cfg(test)] mod tests` block, passing
NWS/BOM/severity/fallback tests, and two measured llvm-cov numbers (baseline + post-Wave-1)
in the SUMMARY. Wire contract stays byte-identical.
</objective>
