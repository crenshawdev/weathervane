<objective>
Verify workspace line coverage is >= 75% on the post-Wave-1 tree (after Plans 05-01
through 05-04 have all merged and their tail tests are compiled in), then add the
`--fail-under-lines 75` flag to the existing `coverage` job in `.gitlab-ci.yml` by
appending it to the existing `cargo llvm-cov report --summary-only` step at line 80.
This is a strictly single-line, single-flag edit — Form A only, no new step
appended, no new comment line inserted.

Purpose: this plan closes out the v0.9.1 milestone by transitively proving COV-07
(workspace line coverage >= 70%) via the stricter D-01 gate value of 75%, and by
committing COV-08 (the failing CI threshold). The 3-point buffer above the milestone
spec of 70% (D-01 rationale: catches real regressions without blocking legitimate PRs
that add a small amount of uncovered code) is baked into the gate.

The sequencing constraint from D-04 is a hard invariant: the CI gate is added ONLY
after Wave 1 has closed the tails and the workspace still comfortably clears 75%.
Task 1 of this plan measures the post-Wave-1 workspace total; if it is below 75%,
Task 2 does NOT commit the gate and the plan STOPS for developer arbitration. The
current 05-CONTEXT.md baseline is 77.87% (2026-07-02, pre-Wave-1). Wave 1 adds
tests to `src/codes.rs`, `src/geo.rs`, `src/time.rs`, and `src/weather_jma.rs`; the
expected effect is a workspace-total INCREASE, but this is not strictly guaranteed:
`cargo llvm-cov` counts `#[cfg(test)] mod tests` blocks as lines of source in the
same file (see Phase 4's own SUMMARY note at
`.planning/phases/04-domain-fetch-parse-coverage/04-02-SUMMARY.md:156`), so a large
new test module on a small source file can dilute per-module percentages even
while the covered-line count goes up. The workspace `TOTAL` is expected to remain
above the pre-Wave-1 baseline of 77.87% and comfortably above the 75% gate — Task 1
verifies this empirically before Task 2 lands the flag.

The .gitlab-ci.yml change is intentionally the last commit of the phase (per D-04
and 05-CONTEXT.md §Specifics: "CI change is intentionally the *last* task in the
phase — added only after the workspace still clears 75% with the new tests in").
The job structure (llvm-tools-preview install, cargo-llvm-cov install-if-missing,
--no-report --workspace, cobertura export, summary-only, artifact + regex) is
preserved byte-identical except for the one flag addition, so the Cobertura MR
widget and the `coverage:` regex both continue to behave as they do today.

Output: one edited `.gitlab-ci.yml` file with `--fail-under-lines 75` appended to
line 80 (single-line, single-flag Form A edit; no new script step, no new comment
line), and one SUMMARY.md file recording the post-Wave-1 workspace coverage number,
the local verify command that passed green, and the diff of the CI file. Wire
contract stays byte-identical; no src/ change.
</objective>
