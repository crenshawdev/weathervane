## Directory Purposes

**src/:**
- Purpose: All Rust source code for the library
- Contains: 18 modules organized by domain (weather, air quality, alerts, pollen) and infrastructure (client, error, wire, geo)
- Key files: lib.rs exports public API; weather.rs, air_quality.rs, alerts.rs are the four main entry points

**tests/:**
- Purpose: Integration tests, specifically wire contract validation
- Contains: wire_contract.rs (insta snapshots) + snapshots/ directory (30 golden JSON files)
- How it works: Test fixtures populate all public types, serialize to JSON, snapshots lock the wire format. Commit snapshots to git. Snapshot test failure = breaking change.

**tests/snapshots/:**
- Purpose: Canonical JSON serialization shapes for each public type
- Contains: 30 `.snap` files generated by insta, one per type variant
- Why committed: They ARE the frozen contract. Changing a snapshot = deliberate breaking change (accept via `cargo insta review`).

**docs/superpowers/:**
- Purpose: Project planning and design documentation
- Contains: Plans and specs for features (e.g., wire contract design from 2026-06-11)

**.claude/:**
- Purpose: Project-specific agent and skill configuration
- Contains: Agent metadata (contract-auditor.md), skill definitions (release-prep/SKILL.md)

**.planning/:**
- Purpose: Generated codebase analysis artifacts
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md (produced by /gsd-map-codebase, consumed by /gsd-plan-phase and /gsd-execute-phase)

## Naming Conventions

**Files:**
- `snake_case.rs`: Module files (weather.rs, air_quality.rs, etc)
- Private modules (only used internally): air_quality_aqicn.rs, weather_jma.rs, client.rs, geo.rs
- Public modules (re-exported from lib.rs): weather.rs, air_quality.rs, alerts.rs, pollen.rs, location.rs, units.rs, codes.rs, time.rs, error.rs, wire.rs, network.rs, sleep.rs

**Types:**
- `PascalCase`: Structs and enums (WeatherData, CurrentWeather, Alert, AlertSeverity, AqiCategory, TemperatureUnit, etc)
- `SCREAMING_SNAKE_CASE`: Constants (USER_AGENT, REQUEST_TIMEOUT, MAX_STATION_DISTANCE_KM, NM_STATE_CONNECTED_GLOBAL)

**Functions:**
- `snake_case`: Public and private functions (fetch_weather, detect_region, format_hour, is_night_time, etc)
- Async functions: prefixed with `async fn` keyword
- Private module functions: use `pub(crate)` for internal-only visibility

**Variables:**
- `snake_case`: Local variables, function parameters
- Static/const: `SCREAMING_SNAKE_CASE`

**Enums/Variants:**
- Enum names: `PascalCase` (WeatherCondition, AlertSeverity, Region)
- Variants: `PascalCase` (ClearSky, PartlyCloudy, Severe, Unknown)

**Error Types:**
- Error variants serialized as strings: "Timeout", "Network", "HttpStatus", "Parse", "HttpClient", "NoResults", "LocationDetection", "Dbus"
- Sub-categories: NetworkKind (Connect, Body, Request, Unknown), ParseKind (Json, Xml)

## Where to Add New Code

**New Weather Provider (e.g., add DMI for Denmark):**
- Create `src/weather_dmi.rs` (private module)
- Define response struct with Deserialize
- Implement `async fn fetch_temp(lat, lon) -> Option<f32>`
- Call from `weather.rs:override_current_temp` replacement (add provider check)
- Test: Add fixture to tests/wire_contract.rs, run `cargo test`

**New Alert Provider (e.g., add JMA for Japan):**
- Add case in `alerts.rs:fetch_alerts` for Region::Japan (if needed)
- Create helper `async fn fetch_jma_alerts(lat, lon) -> Result<Vec<Alert>>`
- Parse XML/JSON response into Alert structs
- Filter expired, deduplicate if needed
- Test: Add Alert fixtures to tests/wire_contract.rs

**New AQI Standard (e.g., add India AQI):**
- Add variant to `air_quality.rs:AqiCategory` enum
- Add category enum `IndiaAqiCategory { ... }` with thresholds
- Update `detect_region` in `geo.rs` to return Region::India
- Add logic in `air_quality.rs:fetch_air_quality` to select standard by region
- Test: Add snapshot for India category, run `cargo insta review`

**New Location Search Provider:**
- Add async function to `location.rs` (e.g., `async fn search_with_geonames(query: &str) -> Result<Vec<LocationResult>>`)
- Call from frontend; update `search_city` if consolidating providers
- Test: Add LocationResult fixtures to tests/wire_contract.rs

**New Utility (e.g., add precipitation_unit):**
- Add to `src/units.rs`: enum `PrecipitationUnit { Mm, Inch }`
- Implement conversion methods (.symbol(), .convert(), .format())
- Re-export from `lib.rs`
- Add snapshot test canary in tests/wire_contract.rs
- Document in API.md

**New D-Bus Stream (e.g., add power state):**
- Create `src/power.rs` (similar to network.rs, sleep.rs)
- Define `pub enum PowerEvent { ... }`
- Implement `pub fn power_stream() -> Pin<Box<dyn Stream<Item = PowerEvent> + Send>>`
- Subscribe to appropriate D-Bus signal (e.g., org.freedesktop.UPower)
- Re-export from lib.rs
- Test: Add to integration suite

## Special Directories

**target/:**
- Purpose: Cargo build artifacts
- Generated: Yes (by `cargo build`)
- Committed: No (.gitignore)
- Contents: Compiled rlibs, binaries, build scripts

**tests/snapshots/:**
- Purpose: Golden JSON files for wire contract (insta snapshots)
- Generated: By test run with `cargo test` and `cargo insta review`
- Committed: Yes (they ARE the contract)
- How to update: Run `cargo test`, then `cargo insta review` to accept changes
