    Rewrite the validation block inside fetch_stations() at src/weather_jma.rs lines 108-122. Current shape silently `continue`s on three failure conditions: non-temperature-reporting stations (elems first byte != b'1'), wrong lat/lon Vec length, and (implicitly) any malformed numeric content that produces an out-of-range decimal degree. Rewrite as follows:

    1. Keep the elems-check arm as-is (line 111-113). Stations that do not report temperature are dropped silently because the JMA station table contains thousands of non-temp stations and logging each would flood debug output. This decision is documented inline in a one-line comment.

    2. Replace the lat/lon length check with an explicit arm that, when the length is wrong, emits `tracing::debug!("dropping JMA station {code}: lat/lon array length mismatch")` and `continue`s. Use the JMA-published station `code` (which the iteration already binds via `for (code, s) in raw`) — do NOT embed the raw `s.lat` or `s.lon` Vec contents in the log message; those are the malformed values being rejected and may exceed what's reasonable to log even as debug data.

    3. After computing `let lat = deg_min_to_decimal(s.lat[0], s.lat[1]);` and `let lon = deg_min_to_decimal(s.lon[0], s.lon[1]);`, add a range check: if `!(-90.0..=90.0).contains(&lat) || !(-180.0..=180.0).contains(&lon)`, emit `tracing::debug!("dropping JMA station {code}: coordinates out of range")` and `continue`. The closed-range predicate also rejects NaN and infinite values (Rust's RangeInclusive::contains returns false for NaN under PartialOrd semantics) — comment that rationale inline so a future "simplify with `lat <= 90.0 && lat >= -90.0`" rewrite cannot silently regress NaN handling.

    4. Push the constructed Station with the now-validated lat/lon onto stations. The existing `tracing::debug!("AMeDAS station table loaded, ...")` summary line at lines 124-127 stays as-is.

    Add two new #[test] fns to the tests module:

Call a small private helper that runs the same validation logic as fetch_stations on the in-memory map (extract the per-entry loop body as a private `fn parse_station_entry(code: String, s: RawStation) -> Option<Station>` if needed for testability; the in-loop logic can stay inline if you prefer to test against a refactored helper). Assert the returned Vec contains exactly one station and the well-formed code is present. If the helper extraction approach is taken, document the rationale (test boundary) in a one-line comment above the helper.
