<objective>
Strip the aqicn API token and any user-built URL query strings from every tracing
and error path produced by the shared HTTP client. Add a tracing-capture leak
harness (wiremock + tracing-test) inline in src/client.rs so any future
regression is caught by `cargo test`. Extend the existing PII assertion block in
tests/wire_contract.rs so WireError serialization is also asserted free of the
sentinel.

Purpose: SEC-01, SEC-02, SEC-05. Closes the highest-severity leak surface
flagged by the security audit — the aqicn `?token=` query parameter reaching
tracing output via `tracing::debug!("{ctx} ... : {e}")` on reqwest::Error.
Output: hardened client.rs, dev-deps added, five sub-tests in client.rs, one
extension to tests/wire_contract.rs.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| aqicn.org -> crate | aqicn API token (caller-supplied) travels in the outgoing URL query string and must never re-enter tracing or wire-error output |
| reqwest -> crate | reqwest::Error carries the request URL via Display; embedding `{e}` in a tracing macro echoes the URL (and any query string) verbatim |
| crate -> tracing subscriber | every `tracing::*!` site is an exfiltration channel for whatever lives in its format arguments |
| crate -> WireError -> consuming process | WireError is serialized to JSON and crosses process boundaries (D-Bus, CLI); any embedded secret leaks into crash buckets and consumer logs |

## STRIDE Threat Register (ASVS Level 1, block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Information Disclosure | `tracing::debug!` sites in `src/client.rs:72,75,95,99` formatting `reqwest::Error` directly via `{e}` | high | mitigate | Task 1 substitutes `e.without_url()` at every site (per D-01). Task 2 leak-assertion harness asserts sentinel absence across all five paths. |
| T-01-02 | Information Disclosure | `From<reqwest::Error> for Error` mapping in `src/error.rs:78-100` reaching `WireError` via `Display` | high | mitigate | The existing mapping already categorises into `NetworkKind` without embedding `e.to_string()`. Task 2 adds `wire_error_never_leaks_aqicn_sentinel` walking `wire_error_exemplars()` to pin that this stays true (per SEC-05, D-04). |
| T-01-03 | Information Disclosure | Future log site formatting a crate-built URL string directly (regression surface, not present today) | high | mitigate | `pub(crate) fn sanitize_url` is available for any future site that wants to log a URL the crate built. Tests in Task 2 assert `!logs_contain("?token=")` so a regression that adds such a site without sanitize_url fails CI. |
| T-01-04 | Tampering | npm/pip/cargo installs (`wiremock`, `tracing-test`) | low | accept | crates.io vetted maintainers (`LukeMathWalker`/`dbrgn` respectively). Both are widely-used test crates; no installs occur at runtime. ASVS L1 does not require legitimacy-gate review at this tier; recorded as accept per `.planning/REQUIREMENTS.md` deferral of DEPS-01/DEPS-02 to a later milestone. |
</threat_model>
