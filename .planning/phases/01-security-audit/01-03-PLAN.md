<objective>
Convert the two D-Bus stream loops in src/network.rs and src/sleep.rs from the
current silent-exit-on-error shape (`while let Some(Ok(msg)) = stream.next()`)
into an explicit match that logs and continues on Err, and from the silent-skip
deserialize shape (`if let Ok(body) = msg.body().deserialize::<T>()`) into an
extracted decode helper that pattern-matches and logs on the Err arm. Pin the
new helpers with unit tests that exercise both wrong-shape and well-formed
bodies, so SEC-04 ("observable at debug level, does not panic") is enforced by
CI.

Purpose: SEC-04. Closes the medium-severity observability gap on the two D-Bus
streams the crate exposes. Output: hardened network.rs, hardened sleep.rs (the
mirror twin), and inline unit tests for both decode helpers.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| NetworkManager (system D-Bus) -> crate | StateChanged signal body is a (u32,) tuple per the NetworkManager spec; a malformed or spoofed signal could carry a different body shape, which the current `if let Ok` silently drops |
| systemd-logind (system D-Bus) -> crate | PrepareForSleep signal body is a (bool,) tuple per the logind spec; same malformed/spoofed risk |
| MessageStream::next() -> stream loop | the stream itself can yield Err items (transport-level D-Bus errors); the current `while let Some(Ok(msg))` shape silently terminates the loop on the first such Err — meaning a single transient D-Bus error kills connectivity-event observability for the rest of the process lifetime |

## STRIDE Threat Register (ASVS Level 1, block on `high`)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Denial of Service | `while let Some(Ok(msg)) = stream.next()` in src/network.rs:57 and src/sleep.rs:55 silently exits the stream on the first MessageStream Err, killing connectivity/sleep event observability | medium | mitigate | D-08: convert loop header to explicit match; Err arm emits tracing::debug! and continues. Tests in this plan pin the decode helper behavior; loop-level Err handling is covered by inspection (no live D-Bus needed). |
| T-03-02 | Tampering | Malformed D-Bus message body (wrong tuple shape) silently dropped at `if let Ok(body) = msg.body().deserialize::<T>()` with no observability | medium | mitigate | D-07: extract decode helper with explicit match; Err arm emits tracing::debug! before returning None. D-09 unit tests assert both wrong-shape (None) and well-formed (Some(value)) paths. |
| T-03-03 | Denial of Service | Malformed D-Bus message panics the stream | low | accept (already-mitigated) | Scout confirmed (CONTEXT.md `<specifics>`): "the current `if let Ok` pattern does not panic; the gap is observability, not panic safety." The transformation in this plan adds observability without altering panic safety. ASVS L1 disposition: accept-as-already-mitigated; the new tests will catch a future regression that does introduce a panic. |
| T-03-04 | Information Disclosure | zbus::Error Display output reaching tracing | low | accept | zbus::Error carries D-Bus protocol detail (bus name, member, interface, transport-level reasons). It does not carry user-supplied secrets — the crate does not pass user data through D-Bus calls (no coords, no tokens). Logging at debug level is acceptable per CLAUDE.md "no PII in errors/tracing" — there is no PII to leak through this surface. |
</threat_model>
